# API DeskHub

Все эндпоинты — read-only (только `GET`), реализованы средствами чистого
Django (`JsonResponse`), без DRF. Формат ответа — JSON.

Базовый префикс: `/api/`

---

## GET /api/coworkings/

Список коворкингов с опциональной фильтрацией.

### Query-параметры (все опциональны)

| Параметр     | Тип    | Описание                                              |
|--------------|--------|--------------------------------------------------------|
| `city`       | string | Название города (точное совпадение)                   |
| `place_type` | string | `Workplace` или `Meeting_room`                         |
| `date`       | string | Дата в формате `YYYY-MM-DD` — только коворкинги со свободными слотами на эту дату |

### Пример запроса

GET /api/coworkings/?city=Владивосток&place_type=Workplace&date=2026-09-01


### Пример ответа `200 OK`
```json
{
  "results": [
    {
      "id": 1,
      "name": "Space Hub",
      "city": "Владивосток",
      "address": "Пр. Космонавтов, д 25",
      "work_time_start": "10:00",
      "work_time_end": "19:00"
    }
  ],
  "count": 1
}
```

### Ошибки
- `400 Bad Request` — недопустимый `place_type` или неверный формат `date`:
```json
{"error": "date должен быть в формате YYYY-MM-DD"}
```

## GET /api/places/{place_id}/slots/

Свободные слоты конкретного места на дату.

### Path-параметры
| Параметр   | Тип | Описание       |
|------------|-----|----------------|
| `place_id` | int | ID места       |

### Query-параметры
| Параметр | Тип    | Описание                                              |
|----------|--------|--------------------------------------------------------|
| `date`   | string | `YYYY-MM-DD`. Если не указан — берётся текущая дата по времени коворкинга |

### Пример запроса

GET /api/places/5/slots/?date=2026-09-01


### Пример ответа `200 OK`
```json
{
  "place_id": 5,
  "place_name": "Рабочее место A1",
  "capacity": 1,
  "date": "2026-09-01",
  "free_slots": [
    {"id": 101, "time_start": "10:00", "time_end": "11:00"},
    {"id": 102, "time_start": "11:00", "time_end": "12:00"}
  ]
}
```

### Ошибки
- `404 Not Found` — место не найдено или неактивно:
```json
{"error": "Место не найдено"}
```
- `400 Bad Request` — неверный формат `date`.

## GET /api/reservations/{reservation_id}/status/

Статус конкретной брони. Доступно только владельцу брони.

### Path-параметры
| Параметр          | Тип | Описание   |
|-------------------|-----|------------|
| `reservation_id`  | int | ID брони   |

### Авторизация
Требуется активная сессия (тот же механизм, что и на сайте — сессионная cookie).

### Пример ответа `200 OK`
```json
{
  "id": 42,
  "status": "awaiting",
  "status_display": "Ожидает",
  "amount_people": 2,
  "place": "Переговорная B2",
  "created_at": "2026-08-20T14:03:11"
}
```

### Ошибки
- `401 Unauthorized` — запрос сделан неавторизованным пользователем:
```json
{"error": "Требуется аутентификация"}
```
- `404 Not Found` — брони с таким ID не существует **или** она принадлежит другому пользователю (специально не различаем эти два случая — иначе через различие в ответе можно было бы перебором ID узнавать, какие брони вообще существуют в системе):
```json
{"error": "Бронирование не найдено"}
```

## Общие правила

- Формат дат в запросах: `YYYY-MM-DD`. Формат дат в ответах для полных datetime: ISO 8601 (`created_at`).
- Все эндпоинты возвращают `Content-Type: application/json`.
- HTTP-коды ответов:
  - `200` — успех
  - `400` — некорректные параметры запроса
  - `401` — требуется аутентификация
  - `404` — ресурс не найден (или недоступен текущему пользователю)
